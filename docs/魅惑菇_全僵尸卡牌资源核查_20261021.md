# 魅惑菇：全僵尸卡牌资源核查

核对日期：2026-10-21。本次为静态遍历查询，未更改游戏代码，未运行游戏或自动化测试。

## 结论

当前普通僵尸枚举共26个有效类型（1～25及1001），全部拥有唯一卡牌模板、非空静态预览及角色场景。无缺卡、重复卡牌身份、空静态预览或已引用资源文件缺失；从卡牌目录和全部普通僵尸场景递归查询到1236个去重资源路径，全部存在。

因此在当前已登记普通僵尸范围内，没有发现“魅惑菇收编后因没有该僵尸的卡牌版本而失败”的类型。此结论针对资源覆盖，不等同于所有种类的局内机制均已实测。

## 查出的类型差异

`scenes/character/zombie/zombie_011_duckytube.tscn` 继承 `zombie_001_norm.tscn`，根节点没有覆盖 `zombie_type`，因此实例实际保留编号1，而非注册入口的11。

收编逻辑使用目标实例的 `target.zombie_type`，所以当前鸭子游泳圈外观的该实例会生成普通僵尸卡；并不会报“没有鸭子卡”，因为编号11的模板本来就存在。其余25个类型的场景身份与注册类型一致。本次仅查询并记录，没有擅自修改鸭子现行类型及关联机制。

## 变体与边界

- 读报第二生命、掉盔橄榄球、落地气球等状态仍使用各自原种类编号，复用该种类基础卡，不需要每种状态再建卡。重新放置为默认新实例，不保留原状态。
- 换装后普通僵尸的编号若已变为路障/铁桶，会得到对应路障/铁桶卡；带路障/铁桶的铁门仍按铁门编号7取得铁门基础卡，不保存额外传播帽子。
- 雪橇小队14和独立队员1001均有自己的模板，不存在只有小队卡、没有队员卡的缺口。
- 僵王不是 `Zombie000Base`，当前魅惑菇收编入口不会选中它；不属于这26种的普通僵尸卡覆盖范围。
- 创建临时卡成功后才清除来源。若未来新增僵尸忘记注册模板，创建接口返回null时不会清除原僵尸，也不会扣魅惑菇费用或开始冷却；但仍需为新类型补齐卡牌才能收编。
